## 一、金额相关（最高优先级）

### 铁律 1：凡是金额显示，必须验证精度

| 重点检查场景 | 说明 |
|-------------|------|
| 0 | 基本场景 |
| 0.00 | 精确到分 |
| 0.01 | 最小金额 |
| 0.10 | 小数点边界 |
| 999999999.99 | 超大金额 |
| 1.1999999 | ❌ 精度错误 |
| 1.2 vs 1.20 | 格式不统一 |

**金融系统精度要求：**
- 人民币：保留 2 位
- 基金份额：可能 4 位
- 利率：可能 6 位以上

> ⚠️ 不要默认相信后端，必须验证

---

### 铁律 2：金额格式必须统一

| 币种 | 正确格式 | 常见错误 |
|------|---------|---------|
| 人民币 | ¥1,234.56 | ¥1234.56 ❌ / ¥1,234.5 ❌ |
| 美元 | $1,234.56 | -1234.56 ❌ |
| 负数 | -¥1,234.56 | ❌ 格式不统一 |
| 零金额 | ¥0.00 | ❌ 可能显示为空 |

---

### 铁律 3：金额颜色不能出错

金融产品大量依赖颜色表达意义：

| 市场 | 盈利 | 亏损 |
|------|------|------|
| A 股 | 🔴 红色 | 🟢 绿色 |
| 港股/美股 | 🟢 绿色 | 🔴 红色 |

**必须检查：**
- [ ] 深色模式
- [ ] 浅色模式
- [ ] 国际化版本

> ⚠️ 很多事故就是颜色反了

## 二、数据展示

### 铁律 4：列表金额与详情金额必须一致

**数据链路验证：**

```
首页 → 资产列表 → 资产详情 → 交易详情
```

**必须核对：**
- [ ] 金额
- [ ] 时间
- [ ] 状态

**常见问题：**
```
详情页取新接口
列表页取旧接口
→ 导致金额不一致
```

---

### 铁律 5：总额一定要校验

**示例：**
```
活期 ¥1,000
基金 ¥2,000
股票 ¥3,000
─────────────────
总资产 ¥6,000 ✅
```

**必须验证：**
```python
1000 + 2000 + 3000 = 6000  # 精确相等
```

> ⚠️ 金融系统经常出现：5999.99 或 6000.01

---

### 铁律 6：百分比必须验证

**检查范围：**
- 收益率
- 涨跌幅
- 手续费率

**边界值：**
- 正数 ✅
- 负数 ✅
- 0% ✅
- 99.99% ✅
- 100% ✅
- 100.01% ✅

## 三、状态类

### 铁律 7：所有状态必须遍历

**订单状态示例：**

| 状态 | 测试 | 说明 |
|------|------|------|
| 待支付 | ✅ | 初始状态 |
| 处理中 | ✅ | 异步处理 |
| 支付成功 | ✅ | 成功路径 |
| 支付失败 | ✅ | 失败路径 |
| 已撤销 | ✅ | 用户主动撤销 |
| 已退款 | ✅ | 退款完成 |
| 退款中 | ✅ | 部分退款 |

> ⚠️ 线上事故 80% 在异常状态，不要只测成功状态

---

### 铁律 8：状态颜色与文案必须匹配

**标准匹配：**

| 状态 | 颜色 | Icon | 文案 |
|------|------|------|------|
| 成功 | 🟢 绿色 | ✓ | 成功 |
| 失败 | 🔴 红色 | ✗ | 失败 |
| 处理中 | 🟡 黄色 | ⏳ | 处理中 |

**检查项：**
- [ ] 颜色是否正确
- [ ] Icon 是否匹配
- [ ] 文案是否一致

---

## 四、时间类

### 铁律 9：时间格式必须统一

**统一规范：**
```plaintext
2026-06-18 15:30:25
```

**检查项：**
- [ ] 秒是否展示
- [ ] 时区是否正确
- [ ] 24 小时制

---

### 铁律 10：跨天边界必须测

**关键时间点：**
```plaintext
23:59:59 → 00:00:00
    ↑ 跨天边界 ↑
```

**场景：**
- [ ] 交易日切换
- [ ] 对账单生成
- [ ] 收益计算

> ⚠️ 很多金融 Bug 都出在跨天

---

### 铁律 11：交易日与自然日不要混淆

**示例 - 周六：**

| 类型 | 日期 |
|------|------|
| 自然日 | 2026-06-20（周六） |
| 交易日 | 2026-06-19（周五） |

> ⚠️ UI 显示容易混淆交易日和自然日

## 五、权限类

### 铁律 12：权限测试必须做

**角色分类：**

| 角色 | 权限级别 |
|------|---------|
| 普通用户 | 基础权限 |
| VIP 用户 | 高级权限 |
| 投顾 | 咨询权限 |
| 管理员 | 管理权限 |
| 审核员 | 审核权限 |

**检查项：**
- [ ] 看不到 - 页面元素是否隐藏
- [ ] 点不到 - 按钮是否禁用
- [ ] 接口拦截 - API 是否返回 403

> ⚠️ 不能只隐藏按钮，必须做接口拦截

---

### 铁律 13：越权访问必须测

**测试方法：**
```plaintext
改 URL：
/account/123  →  /account/124
```

**验证：**
```
是否能看到别人数据 ❌
```

> ⚠️ 金融系统属于高危问题

## 六、输入框类

### 铁律 14：所有输入框测边界

**转账金额边界测试：**

| 测试数据 | 类型 | 预期 |
|---------|------|------|
| 0 | 零 | 提示最小金额 |
| 0.01 | 最小值 | 通过 |
| 0.001 | 小于最小 | 提示错误 |
| 9999999999999.99 | 超大值 | 提示超限 |
| -1 | 负数 | 提示错误 |
| 1000. | 小数点结尾 | 处理 |
| 1000..01 | 双小数点 | 处理 |
| 中文 | 非数字 | 提示错误 |
| 空格 | 空白 | 处理 |
| emoji | 特殊字符 | 提示错误 |

---

### 铁律 15：复制粘贴必须测

**用户复制来源：**
- [ ] 微信复制
- [ ] Excel 复制

**常见问题字符：**
```plaintext
空格 " "
换行 "\n"
Tab "\t"
全角字符 "１２３"
```

**示例：**
```
复制前：1000\n
复制后：1000
     ↓
提交失败 ❌
```

## 七、网络异常类

### 铁律 16：不能只测成功接口

**异常场景：**

| 状态码 | 场景 | 测试 |
|--------|------|------|
| 500 | 服务器错误 | ✅ |
| 502 | 网关错误 | ✅ |
| 503 | 服务不可用 | ✅ |
| 504 | 网关超时 | ✅ |
| 404 | 资源不存在 | ✅ |
| 408 | 请求超时 | ✅ |
| 网络断开 | 断网 | ✅ |

**必须验证错误提示是否友好**

---

### 铁律 17：重复点击必须测

**金融高危场景：**
- 支付
- 转账
- 购买基金
- 提现

**测试方法：**
```bash
连续点击：10次 / 20次
```

**验证：**
```
是否产生重复订单 ❌
是否扣款多次 ❌
```

> ⚠️ 必须做接口幂等性验证

## 八、安全类

### 铁律 18：敏感信息不能裸奔

**脱敏规则：**

| 类型 | 明文 | 脱敏后 |
|------|------|--------|
| 银行卡 | 6222021234567888 | 6222 **** **** 8888 |
| 身份证 | 310123199001011234 | 310***********1234 |
| 手机号 | 13812341234 | 138****1234 |

---

### 铁律 19：截图风险

**检查场景：**
```markdown
App 切后台
  ↓
是否显示：
  ❌ 资产金额
  ❌ 身份证
  ❌ 银行卡
```

**要求：**
- [ ] 模糊处理 ✅
- [ ] 隐藏显示 ✅

> ⚠️ 很多银行 App 要求模糊处理

## 九、兼容性类

### 铁律 20：金融 UI 必须关注极端展示

**极端场景：**

| 字段 | 极端值 | 检查项 |
|------|--------|--------|
| 姓名 | AlexanderChristopherJonathan... | 是否截断/换行 |
| 基金名称 | 超长基金名称测试用.... | 是否截断 |
| 股票名称 | XX银行XX股份有限公司 | 是否截断 |
| 金额 | 999,999,999,999.99 | 是否正常显示 |

**检查项：**
- [ ] 是否截断
- [ ] 是否换行
- [ ] 是否遮挡
- [ ] 是否溢出

## 十、最重要的一条

### 铁律 21：凡是涉及钱，必须验证"三处一致"

**数据一致性验证：**

```plaintext
┌─────────────────┐
│  接口返回值      │  ← API Response
├─────────────────┤
│  页面显示值      │  ← UI Display  
├─────────────────┤
│  数据库值        │  ← Database / Mock Data
└─────────────────┘
        ↓
    三处必须相等 ✅
```

**同一数据必须验证出现在以下位置：**

| 位置 | 必须一致 |
|------|---------|
| 列表页 | ✅ |
| 详情页 | ✅ |
| 导出文件 | ✅ |
| 打印文件 | ✅ |
| 通知消息 | ✅ |

> ⚠️ 只要有一个不一致，就可能是生产事故

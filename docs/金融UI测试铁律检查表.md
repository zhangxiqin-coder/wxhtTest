## 一、金额相关（最高优先级）

### 铁律 1：凡是金额显示，必须验证精度

| 重点检查场景 | 说明 |
|-------------|------|
| 0 | 基本场景 |
| 0.00 | 精确到分 |
| 0.01 | 最小金额 |
| 0.10 | 小数点边界 |
| 999999999.99 | 超大金额 |
| 1.1999999 | ❌ 精度错误 |
| 1.2 vs 1.20 | 格式不统一 |

**金融系统精度要求：**
- 人民币：保留 2 位
- 基金份额：可能 4 位
- 利率：可能 6 位以上

> ⚠️ 不要默认相信后端，必须验证

---

### 铁律 2：金额格式必须统一

| 币种 | 正确格式 | 常见错误 |
|------|---------|---------|
| 人民币 | ¥1,234.56 | ¥1234.56 ❌ / ¥1,234.5 ❌ |
| 美元 | $1,234.56 | -1234.56 ❌ |
| 负数 | -¥1,234.56 | ❌ 格式不统一 |
| 零金额 | ¥0.00 | ❌ 可能显示为空 |

---

### 铁律 3：金额颜色不能出错

金融产品大量依赖颜色表达意义：

| 市场 | 盈利 | 亏损 |
|------|------|------|
| A 股 | 🔴 红色 | 🟢 绿色 |
| 港股/美股 | 🟢 绿色 | 🔴 红色 |

**必须检查：**
- [ ] 深色模式
- [ ] 浅色模式
- [ ] 国际化版本

> ⚠️ 很多事故就是颜色反了

## 二、数据展示

### 铁律 4：列表金额与详情金额必须一致

**数据链路验证：**

```
首页 → 资产列表 → 资产详情 → 交易详情
```

**必须核对：**
- [ ] 金额
- [ ] 时间
- [ ] 状态

**常见问题：**
```
详情页取新接口
列表页取旧接口
→ 导致金额不一致
```

---

### 铁律 5：总额一定要校验

**示例：**
```
活期 ¥1,000
基金 ¥2,000
股票 ¥3,000
─────────────────
总资产 ¥6,000 ✅
```

**必须验证：**
```python
1000 + 2000 + 3000 = 6000  # 精确相等
```

> ⚠️ 金融系统经常出现：5999.99 或 6000.01

---

### 铁律 6：百分比必须验证

**检查范围：**
- 收益率
- 涨跌幅
- 手续费率

**边界值：**
- 正数 ✅
- 负数 ✅
- 0% ✅
- 99.99% ✅
- 100% ✅
- 100.01% ✅

## 三、状态类

### 铁律 7：所有状态必须遍历

**订单状态示例：**

| 状态 | 测试 | 说明 |
|------|------|------|
| 待支付 | ✅ | 初始状态 |
| 处理中 | ✅ | 异步处理 |
| 支付成功 | ✅ | 成功路径 |
| 支付失败 | ✅ | 失败路径 |
| 已撤销 | ✅ | 用户主动撤销 |
| 已退款 | ✅ | 退款完成 |
| 退款中 | ✅ | 部分退款 |

> ⚠️ 线上事故 80% 在异常状态，不要只测成功状态

---

### 铁律 8：状态颜色与文案必须匹配

**标准匹配：**

| 状态 | 颜色 | Icon | 文案 |
|------|------|------|------|
| 成功 | 🟢 绿色 | ✓ | 成功 |
| 失败 | 🔴 红色 | ✗ | 失败 |
| 处理中 | 🟡 黄色 | ⏳ | 处理中 |

**检查项：**
- [ ] 颜色是否正确
- [ ] Icon 是否匹配
- [ ] 文案是否一致

## 四、时间类

### 铁律 9：时间格式必须统一

**统一规范：**
```plaintext
2026-06-18 15:30:25
```

**检查项：**
- [ ] 秒是否展示
- [ ] 时区是否正确
- [ ] 24 小时制

---

### 铁律 10：跨天边界必须测

**关键时间点：**
```plaintext
23:59:59 → 00:00:00
    ↑ 跨天边界 ↑
```

**场景：**
- [ ] 交易日切换
- [ ] 对账单生成
- [ ] 收益计算

> ⚠️ 很多金融 Bug 都出在跨天

---

### 铁律 11：交易日与自然日不要混淆

**示例 - 周六：**

| 类型 | 日期 |
|------|------|
| 自然日 | 2026-06-20（周六） |
| 交易日 | 2026-06-19（周五） |

> ⚠️ UI 显示容易混淆交易日和自然日

## 五、权限类

### 铁律 12：权限测试必须做

**角色分类：**

| 角色 | 权限级别 |
|------|---------|
| 普通用户 | 基础权限 |
| VIP 用户 | 高级权限 |
| 投顾 | 咨询权限 |
| 管理员 | 管理权限 |
| 审核员 | 审核权限 |

**检查项：**
- [ ] 看不到 - 页面元素是否隐藏
- [ ] 点不到 - 按钮是否禁用
- [ ] 接口拦截 - API 是否返回 403

> ⚠️ 不能只隐藏按钮，必须做接口拦截

---

### 铁律 13：越权访问必须测

**测试方法：**
```plaintext
改 URL：
/account/123  →  /account/124
```

**验证：**
```
是否能看到别人数据 ❌
```

> ⚠️ 金融系统属于高危问题

## 六、输入框类

### 铁律 14：所有输入框测边界

**转账金额边界测试：**

| 测试数据 | 类型 | 预期 |
|---------|------|------|
| 0 | 零 | 提示最小金额 |
| 0.01 | 最小值 | 通过 |
| 0.001 | 小于最小 | 提示错误 |
| 9999999999999.99 | 超大值 | 提示超限 |
| -1 | 负数 | 提示错误 |
| 1000. | 小数点结尾 | 处理 |
| 1000..01 | 双小数点 | 处理 |
| 中文 | 非数字 | 提示错误 |
| 空格 | 空白 | 处理 |
| emoji | 特殊字符 | 提示错误 |

---

### 铁律 15：复制粘贴必须测

**用户复制来源：**
- [ ] 微信复制
- [ ] Excel 复制

**常见问题字符：**
```plaintext
空格 " "
换行 "\n"
Tab "\t"
全角字符 "１２３"
```

**示例：**
```
复制前：1000\n
复制后：1000
     ↓
提交失败 ❌
```

## 七、网络异常类

### 铁律 16：不能只测成功接口

**异常场景：**

| 状态码 | 场景 | 测试 |
|--------|------|------|
| 500 | 服务器错误 | ✅ |
| 502 | 网关错误 | ✅ |
| 503 | 服务不可用 | ✅ |
| 504 | 网关超时 | ✅ |
| 404 | 资源不存在 | ✅ |

| 网络断开 | 断网 | ✅ |

**必须验证错误提示是否友好**

### 铁律 17：重复点击必须测

**金融高危场景：**
- 支付
- 转账
- 购买基金
- 提现

**测试方法：**
```bash
连续点击：10次 / 20次
```

**验证：**
```
是否产生重复订单 ❌
是否扣款多次 ❌
```

> ⚠️ 必须做接口幂等性验证

## 十、最重要的一条

### 铁律 21：凡是涉及钱，必须验证"三处一致"

**数据一致性验证：**

```plaintext
┌─────────────────┐
│  接口返回值      │  ← API Response
├─────────────────┤
│  页面显示值      │  ← UI Display  
├─────────────────┤
│  数据库值        │  ← Database / Mock Data
└─────────────────┘
        ↓
    三处必须相等 ✅
```

**同一数据必须验证出现在以下位置：**

| 位置 | 必须一致 |
|------|---------|
| 列表页 | ✅ |
| 详情页 | ✅ |
| 导出文件 | ✅ |
| 打印文件 | ✅ |
| 通知消息 | ✅ |

> ⚠️ 只要有一个不一致，就可能是生产事故

## 附录 A：金融软件特殊边界值清单

### A1. 金额边界值

| 边界类型 | 边界值 | 风险说明 |
|---------|--------|---------|
| **最小值** | 0.00 | 零金额交易 |
| | 0.01 | 最小有效金额 |
| | 0.001 | 精度测试（基金净值） |
| **最大值** | 9,999,999.99 | 单笔限额 |
| | 99,999,999.99 | 日累计限额 |
| | 999,999,999.99 | 系统上限 |
| **临界值** | 1,000.00 | 手续费起收点 |
| | 50,000.00 | 大额交易标准 |
| **精度问题** | 1.001 | 双精度测试 |
| | 1.009999 | 浮点精度问题 |

**常见 Bug：**
```
❌ 1.1999999999（浮点精度）
❌ ¥1,234.（小数点后无数字）
❌ ¥-123.00（负数格式错误）
❌ 1,234,567.89（无货币符号）
```

---

### A2. 时间边界值

| 边界类型 | 边界值 | 场景 |
|---------|--------|------|
| **跨天** | 23:59:59 → 00:00:00 | 交易日切换 |
| **月末** | 2024-01-31 | 2月无31号 |
| **年末** | 12-31 23:59:59 | 年度结算 |
| **闰年** | 2024-02-29 | 闰年2月29日 |
| **节假日** | 春节/国庆 | 节假日计息 |
| **工作日** | 周六/周日 | 交易日判断 |

**跨春节常见问题：**
```
❌ 除夕计息，初一不计息（可能相反）
❌ 周五买入按3天计息，周一按1天
```

---

### A3. 交易类边界值

| 边界类型 | 边界值 | 风险 |
|---------|--------|------|
| **交易密码** | 连续错误3次 | 账户锁定 |
| | 错误5次 | 永久锁定 |
| **转账限额** | 单笔 ≤ 5万 | 普通转账 |
| | 单笔 > 5万 | 需要U盾/人脸 |
| **日累计** | 20万/50万 | 银行不同 |
| **年度累计** | 5万美元 | 外汇管制 |
| **撤销时间** | 交易后24小时 | 可撤销窗口 |

---

### A4. 利率/费率边界值

| 类型 | 边界值 | 说明 |
|------|--------|------|
| **活期利率** | 0.01%~0.35% | 年利率 |
| **定期利率** | 1.1%~3.5% | 1年/3年/5年 |
| **贷款利率** | 3.35%~6% | LPR基准 |
| **手续费率** | 0.1%~1% | 按笔/按金额 |
| **逾期利率** | 正常利率×1.5 | 逾期罚息 |
| **年化收益率** | ±999.99% | 基金/理财 |

---

### A5. 账户类边界值

| 边界类型 | 边界值 | 说明 |
|---------|--------|------|
| **账户数量** | 1+N个子账户 | 资金归集 |
| **用户数** | 同一IP注册10个 | 反薅羊毛 |
| **登录失败** | 5次/小时 | 防暴力破解 |
| **密码长度** | 6~20位 | 密码强度 |
| **用户名长度** | 6~18位 | 用户名规则 |

---

### A6. 合规/风控边界值

| 边界类型 | 边界值 | 说明 |
|---------|--------|------|
| **实名认证** | 未认证/已认证/认证中 | 三种状态 |
| **风险评估** | R1~R5 | 五级风险 |
| **投资限额** | 合格投资者/普通投资者 | 私募产品 |
| **反洗钱** | 单笔1万/累计10万 | 大额可疑报送 |
| **税务申报** | 年收入12万/6万 | 个税汇算清缴 |

---

### A7. 特殊日期边界

| 日期 | 边界值 | 特殊处理 |
|------|--------|---------|
| **春节** | 除夕~初七 | 收益计算特殊 |
| **国债逆回购** | 周四/周五 | 计息天数不同 |
| **基金净值** | T+1/T+2 | 确认日计算 |
| **理财募集** | 募集期/成立日 | 起息日计算 |
| **保险宽限期** | 保费到期60天内 | 宽限期保障 |

**国债逆回购计息规则：**
| 操作日 | 计息天数 |
|--------|---------|
| 周一 | 1天 |
| 周二 | 1天 |
| 周三 | 1天 |
| 周四 | 3天 |
| 周五 | 1天 |

### A8. 必测边界组合

**边界组合测试用例：**

```python
test_cases = [
    # 金额 + 时间
    {"amount": 0.01, "date": "2024-12-31 23:59:59"},
    {"amount": 50000.00, "date": "2024-02-29"},  # 闰年
    
    # 金额 + 限额
    {"amount": 49999.99, "limit": 50000},  # 临界值
    {"amount": 50000.00, "limit": 50000},   # 超限
    
    # 状态 + 金额
    {"status": "待支付", "amount": 0.00},
    {"status": "成功", "amount": 999999999.99},
    
    # 时间 + 节假日
    {"date": "2024-01-01", "holiday": True},
    {"date": "2024-02-10", "holiday": True},  # 春节
    
    # 密码错误次数
    {"wrong_password_count": 3, "expected": "账户锁定"},
    {"wrong_password_count": 5, "expected": "永久锁定"},
]
```

### A9. 高频缺陷速查表

| 缺陷类型 | 常见问题 | 检查项 |
|---------|---------|--------|
| **金额精度** | 1.1999999 | 小数位数 |
| **金额格式** | ¥1234.56 | 货币符号+千分位 |

| **状态流转** | 已撤销→已退款 | 重复退款 |

| **闰年处理** | 2月30日 | 日期合法性 |

### A10. 边界值检查清单

> 💡 测试时逐项核对

```
□ 金额精度：小数位数是否正确
□ 金额格式：千分位/货币符号是否统一
□ 金额边界：最小/最大/临界值是否处理
□ 时间边界：跨天/月/年是否正确
□ 节假日处理：计息/不计息是否正确
□ 状态流转：正向/逆向/超时是否正常
□ 限额控制：单笔/日累计/年累计是否拦截
□ 风控规则：大额/可疑是否上报
□ 合规检查：反洗钱/实名认证是否验证
□ 特殊场景：闰年/夏令时/跨时区是否处理
□ 密码错误：3次锁定/5次永久锁定
□ 交易限额：单笔5万/日累计20万/外汇5万美元
□ 计息规则：国债逆回购/基金净值/理财募集
```
